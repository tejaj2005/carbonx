# Backend deployment and Supabase inputs

Current configuration update: Grok/xAI replaces the local model as the default AI provider. Add XAI_API_KEY in the ignored .env file. Weather, modelled AQ and satellite endpoints are keyless and configured. Official station summaries still need DATA_GOV_IN_API_KEY. No local Ollama runtime is required for the selected configuration. Earlier local-model descriptions below are historical/optional; see ENV_SETUP.md for the active setup.

This is a deployment proposal and requirements list, not a completed Supabase integration. Email is deliberately deferred until the core website, data and deployment path are ready.

## Current autonomous operation

The Express/Node server works without ChatGPT. It serves the website, enforces roles, stores records, runs report processing and polls public metro providers using persisted schedules. In-app notifications are generated by server code.

It must remain running with persistent .data storage. A laptop shutdown or sleeping free host stops monitoring. Local Ollama, if enabled, is a separate running service. A website build alone does not provide a hosted backend.

## Recommended target

| Component                          | Target                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| Public/company/government frontend | HTTPS static hosting                                                                  |
| Identity and records               | Supabase Auth + Postgres with company/government RLS and audited server actions       |
| Reports/exports                    | Private Supabase Storage with authenticated downloads or short-lived signed URLs      |
| Light metro polling                | Supabase Cron → authenticated Edge Function → stored results                          |
| PDF/OCR/COG processing             | Node worker with persistent/durable jobs                                              |
| Free local AI                      | Always-running local/self-hosted Ollama, protected from public unauthenticated access |
| Government email, later            | Approved notification outbox and separate transactional delivery provider             |

Moving to Supabase requires actual adapters/migrations: SQLite schema and queries, current sessions/password identities, file paths, role policies, ownership and public projections. A project URL alone cannot complete it. Existing real data must be backed up before migration; example-only reset and real-record migration are different choices.

## Free-tier constraints verified on 10 November 2026

Official limits can change. Check the linked sources before deployment.

- Free: 500 MB database, 1 GB file storage, 50,000 monthly active users, 5 GB egress and 500,000 Edge invocations; up to two active free projects. https://supabase.com/docs/guides/platform/billing-on-supabase
- Free projects may pause after seven days of low activity. Free service is not guaranteed continuously available. https://supabase.com/docs/guides/platform/free-project-pausing
- Edge: 256 MB memory, two seconds active CPU per request, 150 seconds wall time on Free. The recommendation to keep heavy OCR/imagery/LLM processing in a worker is inferred from these documented limits. https://supabase.com/docs/guides/functions/limits
- Cron can schedule pg_cron/pg_net calls to authenticated functions, with secrets in Vault, independently of ChatGPT. https://supabase.com/docs/guides/functions/schedule-functions
- Private Storage needs RLS and authenticated/signed access; company reports should not be public buckets. https://supabase.com/docs/guides/storage/buckets/fundamentals
- Free backups need user-managed exports/off-site copies. Database backups do not include stored object contents. https://supabase.com/docs/guides/platform/backups

A free pilot is realistic with bounded uploads and a known uptime trade-off. Continuous production enforcement, dependable storage recovery and a continuously available local AI worker require a separately validated hosting arrangement.

## What you need to provide when backend implementation begins

1. Supabase project URL/reference and region, plus whether to migrate existing records or start with demo-only data.
2. Secure project access/environment configuration. Current docs recommend publishable and secret keys over legacy anon/service-role keys. Publishable keys may be used in browser code only with correct RLS. Secret keys and database connection credentials stay server-side; never paste them into chat or commit them. https://supabase.com/docs/guides/getting-started/api-keys
3. A hosting target/account for the Node API and worker, and an always-running machine/service for Ollama if local AI is required.
4. Expected users/reports, maximum upload size, retention period and backup destination.
5. A free data.gov.in API key for official station summaries, plus authorised facility feed details and applicable units/limits/averaging rules for real factory monitoring.
6. A real Government Oversight administrator account/provisioning plan. Example/demo mode should be disabled for normal deployment.

No external account, Supabase project or paid service was created during the UI work.

## Email last

Supabase's default Auth SMTP is an authentication demo mechanism, restricted to team addresses and currently two messages per hour. It is not a general government violation-email service. https://supabase.com/docs/guides/auth/auth-smtp

After backend/data validation, provide the chosen free-tier transactional provider, verified sender/domain, explicit recipient policy and government review/approval rules. Keep notice drafts, approval, retries, delivery IDs and audit history separate from the deterministic alert. Company-reported/model data must not silently become an accusation in an automated email.

Authentication confirmation/password-reset delivery and government operational notices are separate email flows. Neither is implemented by the presentation simulation. No email has been sent.
